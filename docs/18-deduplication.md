# Дубли и слияние клиентов

## Поиск дублей

Реализован одним сервисом `DuplicateFinder` (`find(телефон, email,
исключить_id)`), чтобы его же использовал приём заявок с лендинга
(Фаза 5, `docs/13-landing-api.md`).

Проверяется:
- нормализованный телефон (любое написание сводится к `+7XXXXXXXXXX`);
- email — без учёта регистра и пробелов по краям.

Правила:
- ищутся только не архивные клиенты;
- пустой телефон или email ничего не находят (клиенты без телефона/email
  дублями друг друга не считаются);
- для каждого найденного клиента известно, какие поля совпали (телефон,
  email или оба);
- при редактировании сам клиент исключается из поиска.

В базе нет уникальных ограничений на телефон и email: дубль система не
запрещает, а предупреждает.

## Предупреждение

Только при создании клиента (при редактировании — нет). Если найдены
совпадения, сохранение не выполняется, а над формой показывается панель:
- найденные карточки: имя, телефон, email, что совпало;
- кнопка «Открыть» — переход в существующую карточку;
- кнопка «Продолжить создание» — создаёт нового клиента, повторное
  предупреждение не показывается.

Если после предупреждения телефон или email изменены, поиск выполняется
заново, а «Продолжить создание» действует только для проверенных значений.
Страница автоматически прокручивается вверх, чтобы панель была видна
(важно на телефоне).

## Слияние

Запускается с карточки клиента кнопкой «Объединить с…»:
1. Выбор второго клиента поиском (по имени, телефону, email) среди не
   архивных, кроме текущего.
2. Экран сравнения: две карточки рядом; выбор основной карточки; для
   каждого различающегося поля выбор значения; для примечаний ещё
   вариант «объединить оба текста»; счётчики «Сделки / Задачи /
   Документы» (сейчас нули).
3. По умолчанию берётся значение основной карточки, а если оно пустое —
   значение второй; смена основной карточки пересчитывает выбор.
4. «Объединить» с подтверждением; после слияния открывается основная
   карточка с сообщением.

## Результат

- Основная карточка получает выбранные значения полей.
- Все сделки, задачи и документы дубля переносятся на основного клиента
  (обновлением `client_id` одним запросом на связь; список переносимых
  связей — `ClientMergeService::relations()`, пополняется в Фазах 4, 6, 7).
- Дубль архивируется (`archived_at`), при этом его собственные данные не
  меняются; сохраняется история объединения: `merged_into_id` (куда влит),
  `merged_by` (кем), `merged_at` (когда).
- В истории изменений обеих карточек пишется событие «слияние»: на
  основной «влит клиент X» (с выбранными значениями), на дубле «влит в
  клиента Y».
- Физическое удаление не выполняется.
- Всё выполняется в одной транзакции (при сбое ничего не меняется), а
  карточки блокируются на время слияния, чтобы два пользователя не влили
  одного клиента одновременно.

## Ограничения

Нельзя объединять клиента с самим собой, архивную карточку и уже влитого
клиента (понятная ошибка).

## Доступ

- слияние доступно любому пользователю CRM (создателю и участникам).
