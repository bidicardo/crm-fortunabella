# Переезд на VPS — инструкция для владельца

Что нужно сделать **вам** (не Claude Code), чтобы перенести CRM и лендинг
с хостинга REG.RU Host-0 на VPS Hostkey. Технические подробности —
`docs/23-hosting-constraints.md`; задачи для Claude Code —
`docs/prompts/04-vps-production.md`.

Решения уже приняты: VPS **Hostkey vm.nano** (Москва, 2 ГБ, 560 ₽/мес),
CRM — `crm.fortunabella.ru`, лендинг `fortunabella.ru` — на том же
сервере, база MySQL 8.4, бэкапы — на ваш ПК.

## Когда начинать

После того как закончена Фаза 2 (осталась задача Д3 — список клиентов) и
всё закоммичено. Переезд — отдельная Фаза 2а, четыре шага (20.1–20.4).
Каждый шаг: вы запускаете промпт в Claude Code → он готовит файлы → вы
выполняете их на сервере по инструкции → проверяете → «комит пуш».

## Главные правила

- **Не отключайте хостинг REG.RU Host-0**, пока лендинг и CRM не работают
  на VPS и не перенесена почта (см. ниже). Хостинг и домен — разные
  услуги: домен `fortunabella.ru` продлевается отдельно, его не трогаем.
- Пароли, токены, приватный SSH-ключ и пароль бэкапов **никогда** не
  отправляйте в чат и не кладите в репозиторий. Если скрипт просит их —
  вводите прямо на сервере или на своём ПК.
- Храните пароли в менеджере паролей (например, KeePassXC или Bitwarden).

## Шаг 0. Подготовка (до запуска задачи 20.1)

### 0.1. Почта — проверить, где она работает

Почтовые ящики `@fortunabella.ru`, скорее всего, работают на хостинге
Host-0. Если его отключить, почта перестанет работать.

1. В личном кабинете REG.RU откройте услуги и посмотрите, где созданы
   почтовые ящики (на хостинге Host-0 или отдельной услугой «Почта»).
2. Если на хостинге — до отключения Host-0 перенесите почту: например,
   бесплатная почта для домена (Яндекс 360, Mail.ru для бизнеса) или
   платная почта REG.RU. Это отдельный небольшой переезд — можно сделать
   в самом конце, но **до** отключения хостинга.
3. До этого момента ничего не меняйте в MX-записях домена.

### 0.2. DNS — проверить, где он управляется

В кабинете REG.RU откройте домен `fortunabella.ru` → «DNS-серверы и
управление зоной». Запишите, какие указаны DNS-серверы:

- `ns1.reg.ru`, `ns2.reg.ru` — хорошо, зона живёт у домена и не зависит
  от хостинга;
- `ns1.hosting.reg.ru` и т. п. — зона принадлежит хостингу. Перед
  отключением хостинга нужно перевести домен на `ns1.reg.ru`/`ns2.reg.ru`
  и перенести записи. Скажите об этом Claude Code в задаче 20.3.

### 0.3. Заказать VPS

1. На hostkey.ru выберите **vm.nano**, локация — **Москва**, ОС —
   **Ubuntu 24.04 LTS**.
2. Перед оплатой спросите в поддержке: «Виртуализация KVM? Docker
   работает?» — нужен ответ «да, KVM».
3. После заказа сохраните в менеджер паролей: **IP-адрес сервера** и
   пароль root (он нужен только для первого входа).
4. Узнайте, где в панели Hostkey **веб-консоль** сервера — через неё
   можно войти, если потеряется доступ по SSH.

### 0.4. Создать SSH-ключ на своём ПК

В PowerShell:

```
ssh-keygen -t ed25519 -C "fortunabella-vps"
```

Нажмите Enter на вопрос о пути; задайте пароль ключа (запомните его).
Появятся два файла в `C:\Users\<ваше имя>\.ssh\`:

- `id_ed25519` — **приватный**, никому не отправлять;
- `id_ed25519.pub` — публичный, его можно показывать. Посмотреть:

```
Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub
```

Эту строку (начинается с `ssh-ed25519`) понадобится передать в скрипт
настройки сервера (задача 20.1).

### 0.5. GitHub

- Репозиторий `crm-fortunabella` должен быть **приватным** (Settings →
  General → Danger Zone → Visibility).
- Actions включены (вкладка Actions).
- Токен для сервера (только чтение образов) создадите в задаче 20.3 по
  инструкции.

### 0.6. Файлы лендинга

1. Скачайте с хостинга REG.RU все файлы сайта `fortunabella.ru`
   (файловый менеджер ISPmanager или SFTP через FileZilla) в отдельную
   папку на ПК.
2. Файл с настройками бота (`config.php` или похожий, где токен
   Telegram) **не отправляйте в чат** и не кладите в репозиторий — в
   задаче 20.3 Claude Code скажет, куда положить его на сервере.

### 0.7. Пароль для бэкапов

Придумайте длинный пароль (или сгенерируйте в менеджере паролей) и
сохраните его. Без него бэкапы не восстановить — потерять его нельзя.
В чат не отправлять.

## Шаги переезда (с Claude Code)

| Шаг | Что делает Claude Code | Что делаете вы |
|---|---|---|
| 20.1 Подготовка сервера | скрипт настройки и инструкцию | входите на сервер, запускаете скрипт с вашим публичным ключом, проверяете вход по ключу |
| 20.2 Образ и контейнеры | Dockerfile, `compose.prod.yaml`, настройки HTTPS | проверяете запуск локально по чек-листу |
| 20.3 CI, деплой, лендинг, DNS | сборку в GitHub, скрипт деплоя, перенос лендинга | создаёте токен GHCR, кладёте `.env` и настройки лендинга на сервер, ставите A-записи в DNS, первый деплой, создаёте первого пользователя-создателя |
| 20.4 Бэкапы | скрипты бэкапа, восстановления и забора на ПК | вводите пароль бэкапов на сервере, ставите задачу в Планировщик заданий Windows, делаете пробное восстановление |

Каждый шаг запускается отдельным промптом из
`docs/prompts/04-vps-production.md` (копируете блок кода в Claude Code).

## DNS (в шаге 20.3)

В зоне `fortunabella.ru` в REG.RU:

- `crm` — запись **A** → IP сервера (поддомен бесплатный);
- `@` и `www` — запись **A** → IP сервера (лендинг переезжает);
- MX и записи почты — **не трогать**.

Изменения расходятся до нескольких часов. HTTPS-сертификаты сервер
получит сам, когда записи начнут указывать на него.

## После переезда

1. Проверьте: `https://fortunabella.ru` открывается, форма отправляет
   заявку в Telegram; `https://crm.fortunabella.ru` — вход, клиенты;
   на iPhone — копирование ссылки-приглашения.
2. Неделю поработайте на VPS, убедитесь, что бэкапы приходят на ПК.
3. Перенесите почту (если она на хостинге, см. 0.1).
4. Только после этого отключите хостинг Host-0 (домен не отключать).

## Регулярно

- **Раз в неделю:** проверить, что на ПК появляются новые бэкапы.
- **Раз в месяц:** пробное восстановление по инструкции из задачи 20.4.
- **Раз в месяц:** войти на сервер и выполнить проверку
  (`deploy/check-server.sh`) — обновления и место на диске.
- Следить за оплатой VPS и домена.
