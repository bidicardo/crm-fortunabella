# 19а — Компоновка карточки клиента (референс 6)

Выполняется после Д1 и Д2, до Д3 и до задачи 20. Компоновка станет
образцом для карточек сделки и контрагента (референс 7).

Что нужно от владельца: `docs/design/refs/06-client-card.png` и пометки:
что в референсе — данные клиента, что — будущие связанные блоки
(«Сделки», «Задачи», «Документы»), что убрать или показать крупнее.

```

Этап 1 — спецификация, кода нет: сопоставь референс с реальными
данными карточки. Для каждого блока референса укажи: берём / не берём /
заменяем (например, поля, которых у клиента нет). Покажи схему
компоновки для компьютера и для телефона, где живут: заголовок и имя,
кнопки «Объединить с…» и «Редактировать», основные данные, примечания,
даты, история, заметка об архивной карточке и о слиянии, а также
место под будущие блоки «Сделки», «Задачи», «Документы» (Фазы 4, 6, 7):
показывать ли заглушки сейчас (рекомендую не показывать пустые
заглушки). Список файлов, жди подтверждения.

Этап 2 — реализация (только вёрстка карточки):
1. Переверстай client-show.blade.php по подтверждённой схеме,
   используя компоненты дизайн-системы.
2. Обязательно сохранить поведение: заголовок раздела «Клиент» в верхней
   панели (имя клиента — только в заголовке карточки); кнопки «Объединить
   с…» и «Редактировать» (у архивной карточки их нет); заметка
   «Карточка архивирована» и «Влит в клиента … (ссылка), кем и когда»;
   сообщение об успехе; история изменений: 3 записи, «Показать ещё» до 10
   в блоке с прокруткой внутри (не всей страницы), «Свернуть»; примечания
   с переносами строк; пустые поля как «—»; экранирование вывода.
3. Без горизонтальной прокрутки на телефоне (длинные имена, длинный email,
   кнопки переносятся), светлая и тёмная темы.
4. Не менять данные, PHP-компонент, маршруты и тексты. Если референс
   требует нового поля или блока, сначала спроси.
5. Вынеси повторяемые части (блок-карточка с заголовком, пара
   «подпись — значение», лента истории) в компоненты, которые потом
   переиспользуют карточки сделки и контрагента, только если они
   действительно повторяются; не создавай лишних абстракций.

Существующие тесты проходят без ослабления; поправки ожиданий на разметку
опиши.

В конце: npm run build, composer check (и в Sail), git status и git diff,
ничего не коммить. Дай чек-лист: обычная карточка, карточка без
заполненных полей, с длинными значениями, архивный клиент, влитый дубль,
история (3 → 10 → свернуть); компьютер и iPhone, обе темы.
```
