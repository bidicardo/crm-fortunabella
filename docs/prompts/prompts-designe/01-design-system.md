# Д1 — Дизайн-система (референс 1)

Самый первый шаг дизайна. Выполняется до 19а и до всех остальных
дизайн-шагов. Две части: **Д1а** (спецификация, палитра, шрифты, иконки,
компоненты, витрина) и **Д1б** (перенос уже готовых экранов на
компоненты). Запускать по порядку, между частями проверка владельцем.

Что нужно от владельца до запуска: скриншоты референса 1 в
`docs/design/refs/` (`01-design-system-*.png`: цвета, типографика,
кнопки, поля, иконки и т. д.); иконки — набор Lucide (решение
владельца, `docs/design/README.md`), файлы SVG можно не выгружать заранее:
нужные Lucide-иконки перечислены в спецификации и берутся с lucide.dev
отдельными SVG; ответы на вопросы 1–4 из раздела 7
`docs/26-ui-designe-plan.md` (тёмный вариант палитры, шрифт и кириллица,
набор иконок, логотип).

---

## Д1а — Спецификация, палитра, шрифты, иконки, компоненты

```
Прочитай CLAUDE.md, docs/design/01-themes.md (решения по тёмной и светлой
темам), docs/26-ui-designe-plan.md (раздел «Д1»),
docs/16-pwa-and-mobile.md (правила вёрстки для iPhone),
docs/17-ui-screens.md, docs/design/README.md и все файлы
docs/design/refs/01-design-system-*. Посмотри текущий resources/css/app.css,
vite.config.js (шрифт подключён через bunny() из laravel-vite-plugin),
resources/views/components/* и layouts/*, а также экраны
resources/views/livewire/* — они пока оформлены отдельными наборами
Tailwind-классов.

Этап 1 — спецификация, кода нет. Составь docs/design/01-design-system.md:
1. Цвета: Primary (шкала оттенков с кодами), Grays, Alerts (успех,
   предупреждение, ошибка, информация), статусные цвета для этапов
   сделок (Новая заявка, В работе, Бронь, Проведена, Отказ) и этапов
   контрагентов (подобери из палитры, если в референсе их нет), цвета
   текста и фона в светлой и тёмной теме. Если тёмного варианта в
   референсе нет — предложи вывод из палитры (контраст текста не ниже
   4.5:1).
2. Типографика: шрифт, размеры и начертания заголовков, текста, подписей,
   сочетания текста (заголовок + пояснение и т. п.). Проверь, что шрифт
   поддерживает кириллицу; если нет — предложи ближайшую замену и жди
   решения.
3. Иконки: набор Lucide (ISC), недостающие — Tabler Icons. Составь список
   нужных иконок (по референсу и по экранам: меню, действия, статусы,
   стрелки, календарь, уведомления) с именами Lucide и указанием, где
   каждая применяется; размеры, толщина линии (в Lucide 2, при
   необходимости 1.5 под референс), цвет = currentColor. Сами SVG бери из
   исходников набора (не по картинке) и сохраняй в docs/design/icons/ вместе
   с LICENSE.md (набор, адрес, лицензия). Пакет lucide не устанавливать.
4. Элементы и их состояния (обычное, наведение, фокус, нажатие,
   отключено, ошибка): кнопки (основная, вторичная, опасная, текстовая,
   иконочная), поле ввода, выпадающий список, флажок, радиокнопка,
   переключатель, текстовая область, метка-статус, уведомление (4 вида),
   блок-карточка с заголовком, таблица, пустое состояние, выпадающая
   панель. Скругления, отступы, тени.
5. Список Blade-компонентов и их имена (предложение:
   resources/views/components/ui/*.blade.php, использование
   <x-ui.button>, <x-ui.input> и т. д.) и список файлов, которые будут
   изменены или созданы.
Покажи спецификацию и жди подтверждения. Не пиши код до него.

Этап 2 — после подтверждения:
1. Внеси палитру, шрифты, скругления и тени в переменные оформления
   resources/css/app.css (@theme), тёмную тему сохрани через существующий
   класс .dark. Шрифт подключи тем же способом, что Instrument Sans (см.
   vite.config.js), без CDN и новых пакетов.
2. Обнови компонент иконок x-icon: добавь встроенные SVG Lucide из
   docs/design/icons (без пакетов иконок; сохрани имена уже используемых
   иконок меню: home, deals, clients, counterparties, tasks, calendar,
   documents, заменив их рисунки на Lucide).
3. Создай компоненты из спецификации. Каждый принимает обычные атрибуты
   ($attributes), поддерживает светлую и тёмную темы и доступность
   (связь label и поля, aria-invalid при ошибке, видимый фокус). Поля на
   телефоне должны иметь шрифт 16 px (правило в app.css уже есть — не
   сломай его).
4. Создай временную страницу-витрину со всеми элементами и состояниями в
   обеих темах: маршрут доступен только при APP_ENV=local, в меню не
   попадает, на боевом окружении отвечает 404. Тест: витрина открывается
   локально и отдаёт 404 в production.
5. Pest-тесты: рендер каждого компонента (атрибуты, ошибка, отключено,
   тексты); существующие тесты проходят.

Не переноси существующие экраны на компоненты — это Д1б. Не меняй
логику и тексты.

В конце: npm run build, composer check (и в Sail), git status и git diff,
ничего не коммить. Напиши, что не проверено без браузера, и дай чек-лист:
витрина в светлой и тёмной теме, на телефоне; шрифт с кириллицей;
состояния кнопок и полей; фокус клавиатурой.
```

## Д1б — Перенос готовых экранов на компоненты

```
Прочитай CLAUDE.md, docs/26-ui-designe-plan.md, docs/design/01-design-system.md
и список компонентов resources/views/components/ui. Д1а выполнена.

Перенеси все существующие экраны на компоненты дизайн-системы, чтобы
они выглядели единообразно. Компоновку страниц не менять (её меняют
следующие шаги: Д2, 19а, Д3), логику, данные и тексты тоже.

Что нужно сделать:
1. Экраны: вход, регистрация по приглашению, «Ссылка недействительна»,
   гостевой layout, пользователи (таблицы, приглашения, кнопки),
   список клиентов (панель поиска, фильтры, таблица, пагинация, меню
   колонок), форма клиента (поля, предупреждение о дубле), карточка
   клиента (кнопки, метки, история), слияние клиентов, главная
   (временная заглушка).
2. Каркас: левое меню, верхняя панель, меню пользователя, нижняя панель
   и выдвижное «Ещё», стрелка «Назад» — цвета, шрифты и иконки из
   дизайн-системы. Левое меню остаётся тёмным в обеих темах, если
   референс не требует иного.
3. Убери из шаблонов дублирующиеся длинные наборы классов (например,
   общие переменные $input в client-table и client-form), заменив их
   компонентами.
4. Пагинация Livewire: подключи оформление под дизайн-систему (при
   необходимости опубликуй представление пагинации).
5. Все существующие тесты должны проходить без ослабления. Если тест
   опирался на разметку, поправь его на доступность и текст и напиши,
   что изменил.

Не менять: маршруты, компоненты Livewire (PHP), сервисы, миграции.

В конце: npm run build, composer check (и в Sail), git status и git diff,
ничего не коммить. Напиши, что не проверено без браузера, и дай
чек-лист обхода: каждый готовый экран в светлой и тёмной теме на
компьютере и iPhone, отсутствие горизонтальной прокрутки, фокус
клавиатурой, работа меню колонок и поиска.
```
