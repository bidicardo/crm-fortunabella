# Задача 54 — Итоговая визуальная и мобильная проверка (Фаза 10)

Выполняется после `manifest.json` и service worker (задачи 52–53),
перед push-уведомлениями (55–56). Это не первая мобильная адаптация:
мобильный вид проверялся на каждом дизайн-шаге раньше. Здесь — сквозная
приёмка всех экранов и выравнивание расхождений.

Что нужно от владельца: iPhone для проверки, желательно с установленной
PWA (по HTTPS); логотип и значок для PWA, если они ещё не переданы.

```
Прочитай CLAUDE.md, docs/26-ui-designe-plan.md (раздел «Фаза 10»),
docs/16-pwa-and-mobile.md, docs/17-ui-screens.md, docs/20-acceptance-criteria.md
(раздел «PWA»), docs/design/01-design-system.md. Все дизайн-шаги
выполнены, PWA (manifest, service worker) добавлена.

Этап 1 — аудит, код не менять. Пройди по всем экранам, которые есть в
проекте (список составь по routes/web.php и config/navigation.php) и
для каждого проверь по коду и разметке (браузера у тебя нет — то, что
нельзя проверить, помечай отдельно):
1. Единообразие: используются ли компоненты дизайн-системы, нет ли
   собственных длинных наборов классов, одинаковы ли отступы,
   заголовки, кнопки, метки, пустые состояния.
2. Мобильные правила из docs/16: шрифт полей 16 px, min-h-dvh, безопасная
   зона, размеры нажимаемых элементов не меньше 44 px, нет горизонтальной
   прокрутки страницы (только внутри блоков), длинный текст переносится.
3. Темы: у каждого экрана есть тёмные варианты цветов, контраст текста не
   ниже 4.5:1 (расчёт по палитре), различимы состояния фокуса и ошибок.
4. Доступность: подписи у полей и кнопок-значков, aria-current, aria-expanded,
   порядок фокуса, закрытие панелей по Escape.
5. PWA: значок и заставка, цвет строки состояния и адресной строки
   (theme-color), отсутствие мигания при загрузке, поведение в режиме
   установленного приложения (отступы под вырез и индикатор «домой»).
6. Канбан и календарь: касание, кнопка смены этапа, отсутствие случайных
   перетаскиваний при прокрутке.
Составь таблицу «экран → замечание → серьёзность» и список файлов для
исправлений. Покажи и жди подтверждения, какие замечания править.

Этап 2 — исправления только подтверждённых замечаний, минимальными
правками, на компонентах дизайн-системы. Логику, данные и тексты не
менять. Все тесты проходят.

В конце: npm run build, composer check (и в Sail), git status и git diff,
ничего не коммить. Дай чек-лист ручной проверки на реальном iPhone в
Safari и в установленной PWA: каждый экран из таблицы, обе темы, портрет
и ландшафт, клавиатура над полями, безопасная зона, канбан касанием,
календарь, документы (загрузка и скачивание), выход и повторный вход.
```
