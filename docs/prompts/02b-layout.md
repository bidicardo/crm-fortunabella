# Промпты для Claude Code — Фаза 1а: Каркас интерфейса

Источник задач: `docs/25-architecture-proposal.md` (Фаза 1а, задачи 12.1
и 12.2). Требования: `docs/17-ui-screens.md` (раздел «Навигация и общий
каркас»), `docs/16-pwa-and-mobile.md` (раздел «Навигация на телефоне»),
`docs/14-notifications.md` (колокольчик), `docs/02-mvp-scope.md`.

Выполнять по порядку: 12.1 → 12.2. Фазы 0 и 1 завершены. Делается ДО
Фазы 2 (клиенты), чтобы пункт «Клиенты» сразу встал в меню.

Референс внешнего вида — скриншот EspoCRM, который показал владелец
проекта: тёмная боковая панель с группами и подзаголовками, иконки и
подписи, кнопка сворачивания внизу панели, тонкая верхняя панель.
Копировать нужно структуру и ощущение, а не код.

## Принятые решения (повторно не обсуждать)

- Левое меню сворачивается целиком до иконок; группы всегда раскрыты,
  отдельных раскрывающихся групп нет.
- Состав меню: Главная; группа «Продажи»: Сделки, Клиенты; группа
  «Партнёры»: Контрагенты, Действующие контрагенты; группа «Работа»:
  Задачи, Календарь; Документы.
- Пункт меню показывается только если соответствующий раздел уже
  реализован (то есть существует именованный маршрут). Мёртвых ссылок
  быть не должно, а когда в следующих фазах появятся маршруты, пункты
  появятся сами.
- Верхняя панель: слева название текущего раздела; справа меню
  пользователя (имя со стрелкой вниз). Колокольчика, глобального поиска
  и кнопки «+» сейчас нет (колокольчик появится в Фазе 8).
- Меню пользователя: Профиль, Тёмная тема, Уведомления, Telegram,
  «Пользователи» (только создателю), «Выйти». Пункты, чьих разделов ещё
  нет (Профиль, Уведомления, Telegram), скрыты по тому же правилу.
  Отдельного пункта «Настройки» в левом меню нет.
- На телефоне вместо левого меню нижняя панель вкладок: Главная,
  Сделки, Клиенты, Задачи, Ещё.

## Общие правила для обеих задач

- Стек: Blade + Livewire 4 + Alpine (в комплекте Livewire) + Tailwind 4.
  Иконки — встроенные SVG в Blade-компоненте, без пакетов иконок и
  любых новых зависимостей.
- Интерфейс на русском. Тёмная и светлая темы работают везде.
- Доступность: `aria-label` у навигаций, `aria-current="page"` у
  активного пункта, кнопки — настоящие `<button>`, выпадающее меню
  закрывается по Escape и клику снаружи, `aria-expanded` у кнопок
  раскрытия.
- Тесты — Pest, только выдуманные данные. Запуск: `composer check`,
  а в Sail на Windows `docker compose exec laravel.test composer check`.
  После правки Blade-разметки пересобрать фронтенд: `npm run build`.
- Ничего не коммитить; в конце показать `git status` и `git diff`.
- Внешний вид в браузере ты проверить не можешь, поэтому в конце
  честно напиши, что проверено тестами и HTML, и дай владельцу
  короткий чек-лист ручной проверки.

## Задача 12.1 — Левое меню, верхняя панель, меню пользователя

```
Прочитай CLAUDE.md, docs/17-ui-screens.md (раздел «Навигация и общий
каркас»), docs/25-architecture-proposal.md (Фаза 1а) и этот файл
(решения выше). Посмотри текущий layout
resources/views/layouts/app.blade.php, Livewire-компоненты
app/Livewire (Home, Users, Login, AcceptInvite), routes/web.php и
тесты в tests/Feature — новый код должен их не ломать.

Замени временную шапку полноценным каркасом для десктопа и планшета
(экран от 768 px). Телефон — задача 12.2, но страница не должна
получать горизонтальную прокрутку и на узком экране.

Что нужно сделать:
1. Два layout-а. Основной `layouts::app` (каркас: левое меню, верхняя
   панель, область содержимого) — для страниц после входа. Новый
   `layouts::guest` (`resources/views/layouts/guest.blade.php`:
   по центру, название продукта, маленький переключатель темы) — для
   страницы входа, регистрации по приглашению и страницы «Ссылка
   недействительна». Указать его через атрибут #[Layout('layouts::guest')]
   у Login и AcceptInvite, а в invite-invalid.blade.php использовать
   x-layouts::guest. Общий кусок (скрипт темы до отрисовки, @vite,
   @livewireStyles) не дублировать: вынести в общий partial или
   компонент.
2. Единый источник меню — файл config/navigation.php (только массивы,
   без замыканий, чтобы работал config:cache): группы и пункты с
   полями label, route (имя маршрута), icon, active (список шаблонов
   routeIs для подсветки; шаблоны для «Контрагенты» и «Действующие
   контрагенты» не должны пересекаться — перечисли их явно), tab
   (входит ли в нижнюю панель на телефоне — пригодится в 12.2).
   Имена маршрутов, которые появятся в следующих фазах, договорить
   так: home, deals.index, clients.index, counterparties.index,
   counterparties.active, tasks.index, calendar.index,
   documents.index.
3. Небольшой класс App\Support\Navigation (метод groups()), который
   читает конфиг, отбрасывает пункты с несуществующим маршрутом
   (Route::has), отбрасывает пустые группы и отмечает активный пункт.
   Им будут пользоваться и левое меню, и (в 12.2) нижняя панель.
   Главной странице дать имя маршрута `home` (сейчас у неё нет имени).
4. Левое меню: тёмная панель в обеих темах; вверху название продукта
   (Fortuna CRM); пункты с иконкой и подписью под подзаголовками
   групп; активный пункт подсвечен. Кнопка сворачивания внизу панели:
   свёрнутая панель (~64 px) показывает только иконки, у пункта
   подпись в title, подзаголовки групп скрыты. Состояние хранится в
   localStorage и применяется до отрисовки (без мигания при
   загрузке), как уже сделано для темы. Иконки — Blade-компонент
   `x-icon` со встроенными SVG для: home, deals, clients,
   counterparties, tasks, calendar, documents (простые контурные).
5. Верхняя панель: слева название текущего раздела. Название берётся
   из #[Title('...')] Livewire-компонента (переменная $title в
   layout, она уже используется для тега <title>; сделать <title> в
   виде «Раздел — Fortuna CRM»). Проставить #[Title] у Home
   («Главная») и Users («Пользователи») и убрать повторяющиеся h1
   с тем же названием внутри этих страниц (заголовки подразделов
   оставить). Справа — меню пользователя.
6. Меню пользователя: кнопка с именем и стрелкой вниз открывает панель
   (Alpine, закрытие по Escape и клику снаружи). Пункты в порядке:
   Профиль (route profile), переключатель «Тёмная тема»
   (переиспользуемый компонент x-theme-toggle, тот же, что в guest
   layout), Уведомления (route notifications.index), Telegram (route
   settings.telegram), «Пользователи» (route users, только если
   Gate manage-users), «Выйти» (POST-форма на logout с @csrf). Пункты с
   несуществующим маршрутом не показывать; тема, «Пользователи» и
   «Выйти» есть уже сейчас.
7. Область содержимого: убрать общий ограничитель max-w-3xl из layout,
   отступы p-4 (md:p-6); ширину страниц задают сами страницы. Home
   и Users обернуть в контейнер, чтобы выглядели как раньше.
8. Pest-тесты: в меню есть «Главная» и нет «Сделки»/«Клиенты», пока их
   маршрутов не существует; пункт с существующим маршрутом появляется
   (зарегистрировать тестовый маршрут `clients.index` в самом тесте);
   активный пункт имеет aria-current="page"; «Пользователи» в меню
   пользователя видит создатель и не видит участник; форма выхода
   присутствует; название раздела в верхней панели; страницы входа и
   приглашения не содержат левого меню; тесты существующих функций
   (LoginTest, PermissionsTest, HomeTest) проходят — при необходимости
   поправь их ожидания под новую разметку и напиши, что поменял.
   Отдельный unit-тест на App\Support\Navigation (скрытие
   отсутствующих маршрутов и пустых групп, отметка активного пункта).

Не делать: нижнюю панель для телефона (12.2), колокольчик,
глобальный поиск, кнопку «+», экраны профиля/уведомлений/Telegram,
персонализацию меню.

В конце запусти npm run build и composer check (и в Sail), покажи
git status и git diff, ничего не коммить. Напиши, что не удалось
проверить без браузера, и дай короткий чек-лист ручной проверки:
меню слева, сворачивание и запоминание после F5, подсветка активного
пункта, меню пользователя, переключение темы, выход, вид страницы
входа.
```

## Задача 12.2 — Нижняя панель вкладок на телефоне

```
Прочитай CLAUDE.md, docs/16-pwa-and-mobile.md (раздел «Навигация на
телефоне»), docs/17-ui-screens.md (раздел «Навигация и общий
каркас»), docs/25-architecture-proposal.md (Фаза 1а) и этот файл.
Задача 12.1 выполнена: есть config/navigation.php, класс
App\Support\Navigation, каркас с левым меню и верхней панелью.

Сделай мобильную навигацию для iPhone. Ниже 768 px левое меню скрыто,
вместо него нижняя панель вкладок. Верхняя панель остаётся (название
раздела и меню пользователя).

Что нужно сделать:
1. Нижняя панель (только на экране уже 768 px), закреплена внизу:
   вкладки Главная, Сделки, Клиенты, Задачи и «Ещё». Набор вкладок
   берётся из того же config/navigation.php (поле tab) через
   App\Support\Navigation — отдельного списка не заводить. Вкладки с
   несуществующим маршрутом не показываются, как и в левом меню.
2. «Ещё» открывает выдвижную панель снизу (Alpine): остальные
   разделы из меню (Контрагенты, Действующие контрагенты, Календарь,
   Документы) крупными строками с иконками. Закрывается по Escape,
   касанию затемнённой области и кнопке закрытия. Если ни одного
   такого раздела пока нет — вкладку «Ещё» не показывать.
   «Пользователи», профиль и остальные настройки остаются в меню
   пользователя сверху, в «Ещё» их не дублировать.
3. Активная вкладка подсвечена и имеет aria-current="page";
   «Ещё» подсвечена, когда открыта страница из этой панели.
4. Удобство для iPhone: высота вкладки не меньше 56 px (цель
   касания не меньше 44 px), в <meta name="viewport"> добавить
   viewport-fit=cover, нижняя панель и выдвижная панель учитывают
   безопасную зону (padding-bottom: env(safe-area-inset-bottom)),
   у области содержимого на телефоне нижний отступ, чтобы панель не
   перекрывала контент. Страницы не должны получать горизонтальную
   прокрутку (проверить Home, Users, вход).
5. Переключение между левым меню и нижней панелью — только CSS
   (классы Tailwind md:), без JavaScript-определения размера экрана.
   Обе навигации имеют разные aria-label («Основное меню» и «Нижнее
   меню»).
6. Pest-тесты: в разметке есть нижняя панель с вкладкой «Главная» и
   нет вкладок для несуществующих маршрутов; при появлении маршрутов
   (регистрируются в тесте) появляются вкладки «Сделки», «Клиенты»,
   «Задачи» и «Ещё» с остальными разделами; без разделов для «Ещё»
   эта вкладка отсутствует; у активной вкладки aria-current="page";
   на страницах входа и приглашения нижней панели нет; «Пользователи»
   не дублируется в «Ещё».

Не делать: PWA-манифест и service worker (Фаза 10), жесты
свайпа, колокольчик, персонализацию вкладок, детальную мобильную
адаптацию таблиц и канбана (это задача 54).

В конце запусти npm run build и composer check (и в Sail), покажи
git status и git diff, ничего не коммить. Напиши, что не удалось
проверить без браузера, и дай короткий чек-лист ручной проверки в
режиме устройства браузера (F12, Ctrl+Shift+M, iPhone) и на реальном
телефоне: нижняя панель, «Ещё», подсветка вкладки, отсутствие
горизонтальной прокрутки, отступ под индикатор «домой».
```
