# Промпты для Claude Code — Фаза 0: Bootstrap

Источник задач и решений: `docs/25-architecture-proposal.md` (пункты
1–13 и план задач, Фаза 0, задачи 1–5), ограничения хостинга —
`docs/23-hosting-constraints.md`.

Каждый промпт — самостоятельная сессия Claude Code. Выполнять по
порядку: 1 → 2 → 3 → 4 → 5, каждая следующая опирается на предыдущую.
Перед стартом задачи 1 у Claude Code должен быть доступ к `CLAUDE.md`
и всей папке `docs/` — архитектурные решения уже приняты, повторно их
обсуждать не нужно, только реализовывать.

---

## Задача 1 — Создать проект Laravel 13

```
Прочитай CLAUDE.md и docs/25-architecture-proposal.md (пункты 1, 3, 12
и задача 1 из плана Фазы 0).

Создай новый проект Laravel 13 в текущем репозитории (PHP 8.4,
согласно docs/23-hosting-constraints.md — если PHP 8.4 недоступен
локально, используй PHP 8.5.7 и явно отметь это в README).

Что нужно сделать:
1. Инициализировать проект Laravel 13 через composer create-project
   в корне репозитория (учти, что docs/ и CLAUDE.md уже существуют —
   не затирай их).
2. Настроить .env.example под MySQL/MariaDB (без реальных секретов,
   плейсхолдеры) — параметры БД, APP_URL, APP_TIMEZONE (уточнить
   часовой пояс проекта, если не задан — использовать Europe/Moscow
   и явно пометить как временное решение до ответа на открытый
   вопрос в docs/21-open-questions.md).
3. Создать базовый README.md для разработчика: как поднять проект
   локально (после того как появится Sail — задача 2, пока просто
   опиши шаги через стандартный `php artisan serve` + миграции),
   какие переменные окружения нужны, где искать документацию
   требований (ссылка на docs/).
4. Прогнать штатные тесты Laravel "из коробки" (php artisan test),
   убедиться что они проходят.

Не устанавливай ничего, кроме самого Laravel 13 и его штатных
зависимостей — TALL-стек, Sail, Pint и Pest ставятся в следующих
задачах.

Не удаляй и не изменяй файлы CLAUDE.md и docs/**.

В конце покажи git status и git diff, ничего не коммить.
```

## Задача 2 — Laravel Sail для локальной разработки

```
Прочитай docs/25-architecture-proposal.md (пункт 11 и задача 2 из
плана Фазы 0) и docs/23-hosting-constraints.md.

Настрой Laravel Sail для локальной разработки. Важно: Sail — это
только инструмент для локальной машины разработчика, продакшен
разворачивается без Docker на обычном PHP-FPM (shared-хостинг REG.RU),
это уже решено — не предлагай Docker на проде.

Что нужно сделать:
1. Установить и настроить Laravel Sail с сервисами: PHP (версии, как
   в задаче 1), MySQL/MariaDB, Mailpit.
2. Проверить версию PHP в docker-compose.yml — она должна совпадать с
   версией, выбранной в задаче 1 (см. чек-лист совместимости в
   docs/23-hosting-constraints.md).
3. Обновить .env.example под конфигурацию Sail (хосты БД/почты внутри
   контейнеров).
4. Дополнить README.md: как поднять окружение через `./vendor/bin/sail
   up`, как накатить миграции внутри Sail, как остановить окружение.
5. Убедиться, что `sail up -d` поднимается, миграции по умолчанию
   накатываются (`sail artisan migrate`), штатные тесты Laravel
   проходят внутри контейнера (`sail artisan test`).

Не меняй продакшен-конфигурацию — Sail не должен предполагаться как
способ деплоя.

В конце покажи git status и git diff, ничего не коммить.
```

## Задача 3 — TALL-стек: Tailwind, Alpine.js, Livewire

```
Прочитай docs/25-architecture-proposal.md (пункт 2 и задача 3 из плана
Фазы 0).

Подключи TALL-стек (Tailwind CSS + Alpine.js + Livewire) к проекту.
Это основа фронтенда всей CRM — без отдельного SPA-фреймворка и без
отдельного JSON API для интерфейса (эти решения уже приняты, повторно
не обсуждать).

Что нужно сделать:
1. Установить Livewire (composer-пакет) и убедиться, что базовый
   Livewire-компонент рендерится на тестовой странице.
2. Установить и настроить Tailwind CSS через штатную сборку Laravel
   (Vite) — без ручной конфигурации сборщика с нуля, если Laravel 13
   уже даёт стартовый Vite+Tailwind конфиг.
3. Подключить Alpine.js (обычно идёт вместе с Livewire — не добавляй
   отдельную копию, если Livewire уже её подключает).
4. Поддержать тёмную тему на уровне Tailwind-конфигурации
   (docs/02-mvp-scope.md требует тёмную тему в MVP) — базовый
   переключатель темы, без сложной логики персонализации.
5. Создать один демонстрационный Livewire-компонент (например,
   заглушку главной страницы) и показать, что Tailwind-стили и
   Alpine-интерактивность работают вместе.
6. Обновить README.md: как собрать фронтенд-ассеты локально
   (`npm run build` / `npm run dev`), с учётом что на проде ассеты
   собираются локально/через CI и заливаются готовыми
   (docs/23-hosting-constraints.md, раздел «Деплой»).

Не устанавливай дополнительные UI-библиотеки (компонентные наборы,
иконки-пакеты и т.д.) сверх Tailwind/Alpine/Livewire — они добавляются
по мере необходимости в следующих фазах, не сейчас.

В конце покажи git status и git diff, ничего не коммить.
```

## Задача 4 — Laravel Pint и Pest

```
Прочитай docs/25-architecture-proposal.md (пункт 13 и задача 4 из
плана Фазы 0).

Настрой Laravel Pint для форматирования кода и Pest как основной
тестовый фреймворк проекта (замена/поверх штатного PHPUnit-раннера
Laravel).

Что нужно сделать:
1. Установить Laravel Pint, добавить базовый конфиг (можно оставить
   стандартный пресет Laravel, если он покрывает нужды проекта — не
   изобретай собственный набор правил без необходимости).
2. Прогнать Pint по существующему коду (`./vendor/bin/pint`) и
   убедиться, что репозиторий отформатирован без ошибок.
3. Установить Pest, перевести на него существующие штатные тесты
   Laravel (те, что появились в задаче 1), убедиться что они проходят
   через `./vendor/bin/pest` (или `sail artisan test`, если Sail уже
   настроен в задаче 2).
4. Создать по одному примеру Feature- и Unit-теста как образец
   структуры (например, тест для дефолтного маршрута и тривиальный
   unit-тест) — именно как ориентир для будущих задач, не более того.
5. Обновить README.md: команды для форматирования (`pint`) и запуска
   тестов (`pest`).

Тестовая БД — SQLite in-memory (docs/25-architecture-proposal.md,
пункт 13) — настрой соответствующее тестовое окружение
(`phpunit.xml`/`.env.testing`).

В конце покажи git status и git diff, ничего не коммить.
```

## Задача 5 — Единая команда «тесты + линтер»

```
Прочитай docs/25-architecture-proposal.md (задача 5 из плана Фазы 0)
и CLAUDE.md, раздел «Правила работы Claude Code» (после изменений
всегда запускать тесты и линтер).

Добавь один простой способ прогнать линтер и тесты одной командой —
это не полноценный CI-сервис, а удобный локальный/CI-скрипт для
проверки перед коммитом.

Что нужно сделать:
1. Добавить composer-скрипт (в секцию "scripts" в composer.json),
   например `composer check`, который последовательно запускает:
   Pint в режиме проверки без автофикса (`pint --test`) и Pest
   (`pest`).
2. Задокументировать команду в README.md: «перед коммитом запускать
   composer check».
3. Если в проекте уже есть Sail (задача 2) — убедиться, что команда
   работает и через `sail composer check`.
4. Не настраивай внешний CI-сервис (GitHub Actions и т.п.), если он
   явно не запрошен отдельно — для этой задачи достаточно локального
   скрипта, доступного и человеку, и Claude Code перед каждым коммитом.

Прогони composer check и покажи результат.

В конце покажи git status и git diff, ничего не коммить.
```
