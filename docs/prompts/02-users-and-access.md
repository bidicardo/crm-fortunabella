# Промпты для Claude Code — Фаза 1: Пользователи и доступ

Источник задач: `docs/25-architecture-proposal.md` (Фаза 1, задачи 6–12).
Требования: `docs/03-users-and-permissions.md`, `docs/19-security.md`,
`docs/20-acceptance-criteria.md` (раздел «Пользователи»),
`docs/21-open-questions.md` (раздел «Пользователи»).

Выполнять по порядку: 6 → 7 → 8 → 9 → 10 → 11 → 12. Фаза 0 (Bootstrap)
должна быть завершена: Laravel 13, Livewire 4, Tailwind, Pest, Sail.

## Принятые решения (повторно не обсуждать)

- Только две роли: создатель (`creator`) и участник (`member`).
  Индивидуальных прав участников в MVP нет.
- Регистрации через сайт нет. Первый создатель создаётся консольной
  командой; остальные пользователи — только по приглашению.
- Приглашение: одноразовая ссылка, действует 24 часа. CRM её не
  отправляет — создатель копирует ссылку и передаёт сам.
- Сотрудник сам задаёт пароль при регистрации по ссылке. Смены пароля
  при первом входе нет.
- Восстановления пароля в MVP нет. Не устанавливать Laravel Breeze
  (он приносит регистрацию и сброс пароля, которые нам запрещены) —
  вход пишется вручную на Livewire.

## Общие правила для всех задач Фазы 1

- Интерфейс на русском; стек — Blade + Livewire + Tailwind, общий
  layout `resources/views/layouts/app.blade.php` (тёмная тема уже есть).
- Новые миграции добавлять отдельными файлами, существующие не менять.
  Миграции должны работать и на MySQL (Sail), и на SQLite (тесты).
- Тесты — Pest, SQLite in-memory, только фабрики и выдуманные данные.
  Для нетривиальной логики тест пишется в той же задаче; задача 12
  проверяет полноту покрытия.
- Запуск: `composer check` (Pint + Pest). В Sail на Windows:
  `docker compose exec laravel.test composer check`.
- Не устанавливать новые пакеты без подтверждения. Ничего не коммитить;
  в конце показать `git status` и `git diff`.

## Задача 8 — Модель Invite

```
Прочитай CLAUDE.md, docs/03-users-and-permissions.md, docs/19-security.md и
docs/25-architecture-proposal.md (пункт 5 и задача 8 Фазы 1).

Сделай модель приглашения. Экраны — в задаче 9, здесь только данные
и логика.

Что нужно сделать:
1. Миграция и модель App\Models\Invite:
   - token_hash — sha256-хеш токена, уникальный индекс (сам токен в
     БД не хранится: утечка базы не должна давать рабочие ссылки);
   - created_by — FK на users (создатель);
   - user_id — nullable FK на users (кто зарегистрировался по этому
     приглашению);
   - expires_at — момент истечения;
   - used_at — nullable, когда использовано.
2. Метод создания: Invite::issue(User $creator): array|object,
   возвращающий модель и открытый токен (случайный, не менее 40
   символов, криптостойкий — Str::random или random_bytes). Открытый
   токен доступен только в момент создания.
3. Срок действия — 24 часа (значение вынести в config, например
   config('crm.invite_ttl_hours') = 24; создать config/crm.php только
   если нужного места для настроек ещё нет).
4. Поиск по открытому токену: Invite::findValid(string $token) —
   находит приглашение по sha256-хешу и возвращает его, только если
   оно не использовано и не истекло; иначе null.
5. Метод markUsed(User $user) — атомарно помечает приглашение
   использованным (защита от двойного использования одной ссылки при
   одновременных запросах: условное обновление where used_at is null
   с проверкой числа затронутых строк).
6. Фабрика InviteFactory (состояния expired, used).
7. Pest-тесты: токен не хранится в открытом виде; findValid находит
   валидное; не находит просроченное, использованное и несуществующее;
   markUsed срабатывает ровно один раз.

Не создавать страницы и маршруты — это задача 9.

В конце запусти composer check и покажи git status и git diff,
ничего не коммить.
```
