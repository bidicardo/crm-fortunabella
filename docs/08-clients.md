# Клиенты

## Поля клиента

Обязательное поле — только имя (или название организации).
Остальные необязательны.

- Имя или название организации (обязательно, до 255 символов).
- Телефон — только российский, 11 цифр, хранится как `+7XXXXXXXXXX`.
- Email.
- Социальная сеть или мессенджер.
- Юридический тип.
- Роль.
- Удобное время для связи.
- Примечания.
- Дата создания.
- Дата изменения.
- История изменений.

Служебные поля (в формах не редактируются и через массовое присвоение
не задаются): признак архивации (`archived_at`) и сведения об
объединении (`merged_into_id`, `merged_by`, `merged_at`).

## Тип клиента

Хранится двумя отдельными полями:
- юридический тип: физическое лицо / организация (выбор из списка);
- роль: свободный текст без заданных вариантов (например, «невеста»,
  «организатор», «администратор»), до 255 символов.

## Телефон

Допускаются только российские номера: после удаления всех нецифровых
символов должно остаться 11 цифр, первая — 7 или 8 (8 заменяется на 7).
Иностранные и не сводящиеся к этому формату номера отклоняются.
Правило единое для ручного ввода и заявок с лендинга (`docs/13-landing-api.md`)
и реализовано в одном месте — сервисе `PhoneNormalizer` (форма проверяет
номер правилом `RussianPhone`). Если невалидное значение присвоено модели
напрямую, в БД сохраняется пустое значение.

## Создание и редактирование

- Создание — отдельная страница «Новый клиент» (`/clients/create`); после
  сохранения открывается карточка с сообщением «Клиент создан.».
- Редактирование — прямо в карточке, по одному полю (решение владельца):
  щелчок по полю (или по имени в заголовке) превращает его в поле ввода с
  кнопками ✓ «Сохранить» и ✕ «Отмена»; сохранение также Enter (в
  примечаниях — Ctrl/Cmd+Enter) или выбор варианта в списке «Тип
  клиента», отмена — Esc. Одновременно правится одно поле: щелчок по
  другому полю сначала сохраняет текущее, а при ошибке проверки правка
  остаётся на нём. Каждое сохранение — отдельная запись в истории.
  Отдельной страницы редактирования нет (адрес `/clients/{id}/edit`
  удалён).
- Правила проверки полей общие для создания и правки
  (`Client::validationRules()`).
- При **создании** перед сохранением проверяются дубли (см.
  `docs/18-deduplication.md`); при правке в карточке предупреждения нет.
- Архивную карточку редактировать нельзя: поля не нажимаются, правка в
  обход интерфейса отвечает 403.
- Клиентов нельзя удалять; единственный способ убрать карточку из
  рабочего списка — архивация при слиянии.

## Карточка клиента

Карточка содержит:
- основные данные (пустые поля показываются как «—», примечания с
  сохранением переносов строк), даты создания и изменения;
- кнопку «Объединить с…» и правку полей по щелчку (у архивной карточки
  нет ни того, ни другого);
- для архивной карточки — заметку «Карточка архивирована» и, если это
  влитый дубль, «Влит в клиента … (ссылка), кем и когда»;
- раздел «История изменений»: по умолчанию 3 последние записи, по
  «Показать ещё» — до 10 в блоке с собственной прокруткой, кнопка
  «Свернуть» возвращает 3 записи (что попадает в историю — см. ниже);
- (с Фаз 4, 6, 7) все сделки клиента, задачи и документы, переход в
  связанную сделку.

В верхней панели название раздела — «Клиент»; имя клиента выводится
только в заголовке самой карточки (без дублирования).

Компоновка (задача 19а, референс 6 — `docs/design/refs/06-client-card.png`):
- сверху имя клиента и под ним кнопка «Объединить с…»;
  выше — уведомления (сохранено, карточка архивирована / влит в …);
- на компьютере (от 1024 px) две независимые колонки, блоки своей высоты
  (выравнивать по высоте не нужно — решение владельца): слева данные
  клиента (в рамках полей, по два в строке) и отдельным блоком примечания,
  справа даты «Создан» и «Изменён» и «История изменений»; у блоков данных,
  примечаний и дат заголовков нет;
- на телефоне одна колонка: данные, примечания, даты, история;
- страница создания клиента в той же компоновке: «Имя *» первой строкой
  блока данных, затем поля по два в строке, примечания отдельным блоком;
- места будущих блоков: «Сделки» (Фаза 4) — слева под примечаниями,
  «Задачи» и «Документы» (Фазы 6, 7) — справа; пустых заглушек до их
  появления нет. Эта компоновка — образец для карточек и форм сделки и
  контрагента (`docs/17-ui-screens.md`).

## История изменений клиента

- Пишется автоматически: создание, изменение (только реально
  изменившиеся поля: название поля, было → стало), слияние.
- Автор — текущий пользователь; для системных действий (например,
  заявка с лендинга) автор пустой и показывается как «Система».
- Названия полей русские; юридический тип показывается подписью
  («Организация»), а не значением из БД.
- Служебные и скрытые поля модели в историю не попадают. Поля архивации и
  слияния отдельными записями «изменено» не дублируются — для них есть
  событие «слияние».
- Записи не редактируются и не удаляются из интерфейса; отката по
  истории нет.
- Общий механизм для всех сущностей описан в `docs/04-business-entities.md`.

## База клиентов

Страница `/clients` (раздел «Клиенты» в меню).

- Табличный список: имя (ссылка на карточку), телефон, email,
  соцсеть/мессенджер, тип, роль, «Создан»; колонка «Изменён» скрыта по
  умолчанию. Кнопка «Новый клиент».
- Поиск одной строкой (срабатывает сам, без Enter, после короткой паузы)
  по имени, email, соцсети и роли — подстрока без учёта регистра; если
  запрос состоит только из цифр и знаков номера, то ещё и по телефону
  (8 в начале заменяется на 7). Спецсимволы `%`, `_` в запросе ищутся
  буквально.
- Фильтр по юридическому типу. Отдельного фильтра по роли нет (свободный
  текст), роль участвует в поиске.
- Переключатель «Только архивные»: выключен — показываются только не
  архивные клиенты, включён — только архивные (влитые дубли, с меткой
  «архив»).
- Сортировка по клику на заголовок: имя, «Создан», «Изменён»;
  направление видно (▲/▼).
- Выбор отображаемых колонок (чек-боксы); «Имя» скрыть нельзя. Выбор
  хранится в браузере пользователя (`localStorage`), не на сервере.
- Постраничный вывод по 25 записей. Поиск, фильтр, архив и сортировка
  сохраняются в адресе страницы.
- Пустое состояние: «Клиентов не найдено».
- Таблица на телефоне прокручивается внутри своего блока, а не всей
  страницей.
- (Фаза 4) Фильтрация по статусу сделок и цветовое обозначение строки по
  статусу сделки — способ для случая нескольких сделок у клиента пока не
  решён (`docs/21-open-questions.md`).
- Экспорт в Excel — опционально, не в MVP.

## Слияние дублей

Любой пользователь CRM (создатель или участник) может выбрать две
карточки и объединить их. Подробности — `docs/18-deduplication.md`.

Перед объединением показываются:
- основная карточка и карточка-дубль;
- поля, которые будут сохранены (выбор значения для каждого
  различающегося поля);
- сделки, задачи, документы (сейчас счётчики с нулями, реальные данные
  появятся в Фазах 4, 6, 7);
- история.

Дублируемая карточка архивируется, физическое удаление не выполняется.
