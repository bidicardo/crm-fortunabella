# Пользователи и права доступа

## Типы пользователей

### Создатель

Создатель CRM имеет полный доступ к системе.

Может:
- приглашать участников;
- создавать одноразовые ссылки-приглшения;
- блокировать участников;
- разблокировать участников;
- просматривать и изменять все данные;
- создавать и изменять клиентов;
- создавать и изменять контрагентов;
- создавать и изменять сделки;
- создавать задачи;
- загружать и удалять документы;
- просматривать историю изменений;
- объединять дубли клиентов.

В MVP только две роли: создатель и участник. Индивидуальная настройка
прав участников (чек-боксы: редактирование клиентов, сделок и т. д.)
отложена на следующие версии.

### Участник

Участник имеет те же права, что и создатель,
за исключением управления пользователями.

Участник не может:
- создавать приглашения;
- приглашать новых участников;
- блокировать пользователей;
- разблокировать пользователей;
- изменять права пользователей.

## Приглашение

- Приглашение создаёт только создатель.
- Приглашение содержит одноразовый токен.
- Токен действует 24 часа.
- Токен нельзя использовать повторно.
- CRM не отправляет приглашение сама: создатель копирует ссылку и
  передаёт её сотруднику самостоятельно (мессенджер и т. п.).
- Сотрудник переходит по ссылке.
- Сотрудник самостоятельно задаёт пароль.
- После регистрации токен становится недействительным.
- После использования ссылка не должна открывать форму регистрации.
- Создатель может деактивировать ещё не использованное и не истёкшее
  приглашение (кнопка «Деактивировать» в списке приглашений): ссылка
  сразу перестаёт работать, статус — «деактивировано».
- Создатель может заблокировать учётную запись.

## Авторизация

- На странице входа нет открытой регистрации.
- Пользователь может попасть в CRM только после авторизации.
- Новый сотрудник регистрируется только по приглашению.
- Пароли хранятся только в хешированном виде.
- Отдельной смены пароля при первом входе нет: пароль задаётся один раз
  при регистрации по приглашению.
- Восстановление пароля в MVP не реализуется. При утере пароля доступ
  восстанавливается вручную через базу данных.
- Первого создателя нельзя зарегистрировать через сайт: он создаётся
  консольной командой при развёртывании.
